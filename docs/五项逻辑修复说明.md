## 修复结果

| 问题 | 当前代码处理 |
| --- | --- |
| 补录旧评估误暂停计划 | 写入前锁定老人；移除按本次插入等级暂停的分支；统一过程取当天及以前最新评估，再判断过期或等级与服务包不匹配。已有较新有效评估时，补录更旧记录不会暂停计划。手动恢复计划流程保留 |

| 证书类型非空而等级为空 | 新建库使用具名CHECK，显式检查非空及1—3等级；旧库经迁移补装同一约束。两项同空合法，只有一项为空或等级越界不合法 |

| 质量抽查跨辖区 | 有订单目标的抽查按订单历史社区判断，直接护工抽查按护工服务区域判断；不再把两个范围无条件合并。分页计数和记录查询使用同一条件，机构和护工本人规则保持原有含义 |

## 已有数据库更新

在项目目录停止正在使用该库的服务后，使用原有开发环境执行：

```powershell
.\.venv\Scripts\python.exe scripts/manage.py migrate
```

`migrate` 先运行 `sql/migrations/20261117_five_logic_fixes.sql`：列出不合法证书要求或重复采集的记录并中止，不自动删除、合并或修改历史值。全部预检通过后，更新约束、视图、过程、触发器及权限，并统一提交；任何步骤失败会回滚本轮更新。可重复运行，已有数据库不会重建表。

更新成功后重新使用原有 `start.ps1` 或一键启动脚本启动服务，使Python代码与数据库过程同时使用本次版本。

全新数据库仍使用 `init`，会采用同样的具名约束并加载更新脚本。表数仍为33；增加一个采集身份触发器后，触发器总数为15。
