# 操作留痕中的 scheduler tick 噪声（2026-11-17）

## 现象

“操作留痕”列表第一页连续出现 `scheduler`、`tick`、`{"expiry":{"paused_plans":0,...` 这样的行，看起来像乱码。

不是编码问题：`detail` 列原样显示的是维护任务写入的 JSON，列表只截取前 38 个字符，所以一行 JSON 被截成半截，配合连续多行相同的值，看起来就像乱码。

## 原因

`scripts/maintenance.py` 每 60 秒执行一次 `tick()`，原实现无论有没有实际处理数据，都会写一条：

```python
db.audit("scheduler", 0, "tick", None, json.dumps(result, ensure_ascii=False))
```

演示库累计了 17 条空转记录；列表每页 20 条，这些记录足以占满第一页，把真正的业务操作挤到后面。

## 修复

- `scripts/maintenance.py`：只有 `paused_plans`、`released_assignments`、`escalated_count`、`notifications` 任一非 0 时才写审计；`action` 改为 `maintenance`，`detail` 改为中文摘要，不再写 JSON。
- `care/queries.py`：`audit` 列表排除历史 `entity='scheduler' AND action='tick'` 的行；真正发生维护动作的 `maintenance` 行仍会显示。
- 历史 17 条未删除，保留在 `audit_log` 中，仅不在“操作留痕”页面显示；如确实要清理，可另行归档后删除。

## 验证

- 空转 `tick()` 前后 `audit_log` 总数 164 → 164，未新增记录。
- 管理员“操作留痕”：147 条（164 − 17），首行为 `#0147`（护工 / 修改），不再出现 scheduler tick。
- `.venv\Scripts\python.exe -m pytest tests -q` → **65 passed in 51.29s**。
- `.venv\Scripts\python.exe scripts\verify_ui.py` → **8 pages / javascript_errors=[] / delayed_navigation=passed / mobile 390×844 / result=passed**。
- 截图：`docs/evidence/screenshots/audit.png`（该页不在 `verify_ui.py` 的 8 页列表内，为本次单独补拍）。

## 备注

`verify_ui.py` 原来用 `page.wait_for_function("...")` 等待页面状态，在当前 CSP（`script-src 'self'`）下会触发 `unsafe-eval` 限制；本次改成 `page.wait_for_selector('#workspace[data-section="..."]')`，等待语义不变，也不再依赖页面内 `eval`。
