## 七项修改

| 问题 | 修复后的规则 |
| --- | --- |
| BE01 异常恢复不能签退 | 恢复时读取当前派单的工时。没有签退则回到服务中，可继续原签退操作；已有签退则回到待确认。缺少工时记录时要求先核实，不直接进入错误阶段 |
| BE02 终止服务阻止下一单 | 新单签到仅受未结束业务的未签退记录阻断，已终止、已取消订单不再阻断。终止时仍保留原始工时、原因及已使用班次容量，不虚构签退时间或可结算工时；未结束的异常仍会阻断 |
| BE03 更新标签重置坐标 | 更新前锁定档案；未提交经纬度时保留原值，明确提交的新坐标按原接口写入。迁移社区、改变地址也不会自动把实际住址替换为社区中心；需要变更坐标时由现有接口明确提供 |
| BE04 体征重传精度 | 保存和重传比较均先转换为Decimal，按四舍五入保留两位小数，与decimal(8,2)一致；非数字、无穷值或超范围输入返回业务错误。相同保存精度的值返回旧编号，真正不同的值仍报冲突 |
| BE05 反馈互相覆盖 | 更新前锁定订单；未提交字段保留。兼容现有未回填文本的表单，空白评价/投诉表示不修改；JSON显式null表示清空。评分按明确提交值更新。投诉文字变更或清空时，清除针对旧投诉的处理结论，其他字段不受影响 |
| BE06 直接护工抽查权限 | 街道/民政直接抽查和复核，与列表统一为至少一个护工服务社区在辖区内；没有任何交集则拒绝。订单目标仍按订单历史社区授权，不借护工跨区服务扩大订单范围。整改处理锁定抽查行，保留机构提交和监管复核分工 |
| BE07 迁移后申报重交 | `sp_claim_month`在锁定老人和对应申报后判断实际账号：首次提交看老人当前社区，已有申报看首次申报社区。原社区能补材料，迁入社区不能接管旧申报。管理员沿用原权限，HTTP越权返回403 |

## 数据库更新与启动

先停止当前服务，在项目目录使用原有虚拟环境执行：

```powershell
.\.venv\Scripts\python.exe scripts/manage.py migrate
```

本轮修改的SQL位于现有 `sql/03_procedures.sql`，已有迁移命令会自动加载。没有新的表或列需要建立。上一轮的存量预检和全事务提交机制继续使用。

迁移成功后，再通过原有启动脚本重启服务，使后端和过程同时采用本次版本。仅复制Python文件而没有更新过程，会保留旧申报权限规则。

## 接口兼容说明

- 路由和必填参数不变，前端无需更换调用地址。
- `/api/orders/{id}/feedback`：缺字段或空白文本保留旧值；`feedback: null`、`complaint: null`可明确清空。评分明确提交时更新，未提交时保留。
- `/api/claims`：原参数照常使用；已有月度申报按其保存社区授权，首次申报按当前社区授权；越权返回403。
- 已终止的历史未签退记录不需要补造时间，新签到查询会按订单终态识别。
