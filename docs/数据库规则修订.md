# 数据库规则修订

本次修订只落实已有的服务确认和补贴审核要求，不新增表，不修改前端。

- `tr_assignment_slots`：确认人、确认时间须同时填写或清空。新增或变更确认时，核验启用账号、老人本人身份或该老人联系人在确认时点的有效授权。未变更的历史确认不因后续撤销授权而失效。
- `sp_finish_order`、`tr_order_completion`：完成条件同时要求确认人非空和确认时间覆盖签退时间。
- `sp_review_claim`：终审必须存在最近一次退回记录之后的街道初审通过记录；继续执行原有的辖区、提交人回避及历次初终审人员分离校验。
- `care_runtime`：禁止直接新增、修改、删除补贴申报、申报明细、审核记录。应用通过现有的申报、审核、拨付存储过程写入，过程内部静态 SQL 通过 dbo 所有权链执行。
- `tests/test_database.py`：补充确认字段配对、错误身份、授权失效、历史有效确认保留、直接写表被拒绝、受限身份合法审核全流程和本轮初审校验场景。

## 更新已有数据库

在项目目录使用有权限更新数据库对象的原开发账号执行：

```powershell
.\.venv\Scripts\python.exe scripts/manage.py migrate
```

无需重新建库或重新装载数据。该命令更新视图、函数、存储过程、触发器和数据库权限，不重建业务表。

本次仅修改代码并进行静态检查，未执行数据库迁移或集成测试。原有历史测试报告不代表本次修订后的测试结果。
